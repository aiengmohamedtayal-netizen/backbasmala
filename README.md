# محلل المسار المهني بالذكاء الاصطناعي — الـBackend

ده الـBackend الخاص بمشروع **AI Smart Career Analyzer**. وظيفته يستقبل طلبات الـAPI، ويسجّل المستخدمين ويدير تسجيل الدخول، ويحلّل ملفات الـCV، ويقارن المهارات بالوظائف المستهدفة، ويجهّز خطة تعلّم، ويتابع تقدّم المستخدم.

المشروع معمول باستخدام **FastAPI وPython وSQLite وJWT**.

---

## 1. المشروع بيعمل إيه؟

- إنشاء حساب جديد وتسجيل الدخول.
- التأكد من هوية المستخدم باستخدام JWT.
- رفع ملفات السيرة الذاتية PDF أو DOCX وتحليلها.
- استخراج المهارات ومقارنتها بمتطلبات الوظائف.
- توضيح المهارات الناقصة وتجهيز خطة تعلّم.
- حفظ تقدّم المستخدم في خطة التعلّم.
- توفير نقطة ربط لمساعد ذكي؛ لكن ربط مزوّد الذكاء الاصطناعي الفعلي لسه محتاج إعداد.

## 2. التقنيات المستخدمة

- **FastAPI:** لبناء الـAPI.
- **Uvicorn:** لتشغيل السيرفر.
- **SQLite:** قاعدة بيانات محلية، من غير ما تحتاج تثبّت Database Server منفصل.
- **JWT / PyJWT:** لإدارة الـaccess tokens.
- **PBKDF2-HMAC-SHA256:** لتشفير كلمات المرور قبل حفظها.
- **pdfplumber وpython-docx:** لقراءة محتوى ملفات PDF وWord.

## 4. المتطلبات قبل التشغيل

هتحتاج:
- Python إصدار متوافق مع المشروع (يفضّل Python 3.11 أو 3.12).
- Git.
- اتصال بالإنترنت وقت تنزيل الحزم.

## 5. نزّل المشروع وجهّزه

### أولًا: نزّل نسخة من GitHub

```bash
git clone https://github.com/aiengmohamedtayal-netizen/backbasmala.git
cd backbasmala
```

### ثانيًا: اعمل بيئة Python مستقلة

على **Windows PowerShell**:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

لو PowerShell منع تشغيل سكريبت التفعيل، تقدر تستخدم مفسّر البيئة مباشرة بدل تغيير إعدادات أمان الجهاز.

على **Linux أو macOS**:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### ثالثًا: نزّل الحزم

```bash
python -m pip install -r requirements.txt
```

ولو هتشغّل الاختبارات كمان:

```bash
python -m pip install -r requirements-dev.txt
```

### رابعًا: جهّز ملف البيئة

انسخ الملف النموذجي باسم `.env`.

على Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

على Linux أو macOS:

```bash
cp .env.example .env
```

ولّد قيمة سرية جديدة:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

افتح ملف `.env` وحط القيمة اللي اتولدت بعد `SECRET_KEY=`. احتفظ بالملف ده على جهازك، **ومتعملوش commit أو push على GitHub**.

متغيرات البيئة المهمة:
- `SECRET_KEY`: مفتاح سري لتوقيع الـJWT.
- `CORS_ORIGINS`: عناوين الـFrontend المسموح لها تكلم الـBackend، وافصل بين كل عنوان والتاني بفاصلة.
- `TOKEN_DAYS`: مدة صلاحية الـToken بالأيام؛ القيمة الافتراضية 7.
- `DATABASE_PATH`: مكان قاعدة SQLite، وده اختياري.

## 6. شغّل الـBackend

من داخل مجلد المشروع، وبعد تفعيل البيئة وتثبيت الحزم:

```bash
python -m uvicorn main:app --reload --port 8000
```

لو السيرفر اشتغل، هتلاقيه متاح على:

- عنوان الـAPI: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- توثيق وتجربة الـAPI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- توثيق بديل: [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)

## 7. إعداد قاعدة البيانات

المشروع بيستخدم SQLite، والجداول بتتجهّز تلقائيًا عند تشغيل التطبيق عن طريق `init_db()`.

افتراضيًا، ملف قاعدة البيانات اسمه `careerly.db` في جذر المشروع، وتقدر تغيّر مكانه باستخدام `DATABASE_PATH`.

لو محتاج تبدأ بقاعدة بيانات محلية جديدة، أوقف السيرفر الأول، وبعد التأكد إن الملف مفيهوش بيانات مهمة احذف `careerly.db`، وبعدها شغّل السيرفر تاني. **ما تحذفش قاعدة بيانات فيها بيانات مهمة من غير نسخة احتياطية.**

## 8. استخدام الـAPI

### فحص إن السيرفر شغال

**الطلب:** `GET /`

مش محتاج Token. المفروض يرجع رد يؤكد إن التطبيق شغال.

### إنشاء حساب

**الطلب:** `POST /auth/register`

Body بصيغة JSON:

```json
{
  "name": "اسم المستخدم",
  "email": "user@example.com",
  "password": "StrongPassword123"
}
```

الـAPI بيدعم أسماء العرض المتوافقة مع الـschema، زي `name` أو `full_name` أو `username`.

لو الحساب اتعمل بنجاح، الاستجابة بتكون `201 Created` ومعاها بيانات المستخدم والـaccess token. لو البريد مستخدم قبل كده، المفروض يرجع `409 Conflict`. ولو البيانات مش صحيحة، هيرجع خطأ validation زي `422`.

### تسجيل الدخول

**الطلب:** `POST /auth/login`

```json
{
  "email": "user@example.com",
  "password": "StrongPassword123"
}
```

لما البيانات تكون صحيحة، المفروض يرجع `200 OK` ومعاه الـtoken وبيانات المستخدم. كلمة السر الغلط أو بيانات الدخول غير الصحيحة بترجع `401 Unauthorized`.

بعد تسجيل الدخول، احتفظ بالـtoken في الـFrontend بالطريقة المناسبة، وابعتُه مع أي طلب محمي في الهيدر بالشكل ده:

```text
Authorization: Bearer <access_token>
```

### التأكد من المستخدم الحالي

**الطلب:** `GET /auth/me`

لازم تبعت الـBearer Token. لو صالح، الـAPI بيرجع بيانات المستخدم الحالي. من غير Token أو باستخدام Token غير صالح، الطلب بيرفض.

### الوظائف المتاحة

| الطلب | بيعمل إيه؟ | محتاج Token؟ |
|---|---|---|
| `GET /` | يتأكد إن السيرفر شغال | لأ |
| `POST /auth/register` | ينشئ حساب جديد | لأ |
| `POST /auth/login` | يسجّل دخول المستخدم | لأ |
| `GET /auth/me` | يرجّع بيانات المستخدم الحالي | أيوه |
| `GET /roles` | يعرض الوظائف المستهدفة المتاحة | لأ |
| `POST /cv/upload` | يرفع الـCV ويحلله | أيوه |
| `GET /analysis/latest` | يرجّع آخر تحليل للمستخدم | أيوه |
| `PATCH /learning/progress` | يحدّث حالة مهارة في خطة التعلّم | أيوه |
| `POST /chat` | نقطة ربط لمساعد مهني ذكي | أيوه |

للتفاصيل الدقيقة عن الـRequest والـResponse، افتح `/docs` بعد تشغيل السيرفر؛ ده المرجع العملي المطابق للـAPI الموجود في النسخة الحالية.

## 9. تشغيل الاختبارات

ثبّت متطلبات التطوير لو لسه ما ثبتّهاش:

```bash
python -m pip install -r requirements-dev.txt
```

بعدها شغّل الاختبارات:

```bash
python -m pytest -v tests
```

آخر نتيجة مسجّلة قبل تحديث التوثيق كانت **21 اختبار ناجح واختبار واحد متخطّي**؛ الاختبار المتخطّي متعلق بتوليد PDF الاختياري عند عدم توفر مكتبة `reportlab`. شغّل الاختبارات على جهازك عشان تتأكد من النتيجة في بيئتك.

وتقدر تتأكد من سلامة صياغة ملفات Python بالأمر:

```bash
python -m compileall -q app careerly_core tests main.py
```

## 10. ملاحظات مهمة قبل التسليم أو النشر

- قبل نشر الـFrontend، أضف عنوانه الفعلي إلى `CORS_ORIGINS` في إعدادات البيئة.
- متشاركش `.env` أو أي JWT أو كلمة سر على GitHub أو في الرسائل.
- كلمات المرور بتتخزن كـhash، مش كنص واضح.
- قاعدة SQLite هنا محلية؛ لو هتنشر التطبيق على Hosting، راجع إن مكان التخزين دائم ومناسب لطبيعة الخدمة.
- مسار الشات لسه محتاج إعداد وربط مزوّد الذكاء الاصطناعي عشان يقدم الوظيفة كاملة.
- اختبار PDF الاختياري ممكن يحتاج تثبيت `reportlab` ضمن بيئة الاختبار.
- نجاح الاختبارات المحلية مش لوحده دليل على إن النشر الفعلي جاهز؛ لازم إعداد الـsecrets والـdatabase والـCORS في بيئة الاستضافة.

## 11. ملفات مهمّة للمراجعة

- `main.py`: تشغيل التطبيق وإعدادات الـCORS.
- `app/routes/auth.py`: إنشاء الحساب وتسجيل الدخول والجلسة.
- `app/security.py`: التحقق من كلمات المرور والـJWT.
- `app/config.py`: إعدادات البيئة.
- `app/db.py`: عمليات قاعدة البيانات.
- `tests/`: الاختبارات اللي بتساعد تتأكد إن السلوك الأساسي لسه شغال.

لو بتستلم المشروع لأول مرة، ابدأ من خطوات الإعداد والتشغيل فوق، وبعدها افتح `/docs` وجرب الـendpoints.
